THE CATCH-UP — the architecture notes, the likes count, and the copy-paste worm

The second day of the checkable artifact brought exactly the kind of follow-up the record was built to surface: a detailed architecture analysis from a researcher who read the technical report, not the press release. Sebastian Raschka published "Kimi K3 Architecture Notes" on July 28, walking through the architecture component by component. The headline finding is that K3 is a scaled-up production version of the Kimi Linear model Moonshot released last year — scaled from 48 billion parameters to 2.8 trillion — with one genuinely new component (LatentMoE, shared with Nemotron 3 Ultra, which compresses large linear layers via down-projection) and a number of inference-efficiency tweaks familiar from the current generation of frontier models. More interesting than the new component is the one that was removed: K3 uses NoPE — No Positional Embeddings — everywhere, having eliminated all Rotary Position Embedding layers. This makes it the first frontier-level model to run entirely without explicit position encoding, a choice that the architecture notes treat as inherited from Kimi Linear but the absence of which is remarkable given that the rest of the field has been moving toward hybrid schemes (RoPE in local attention, NoPE in global layers). The attention residuals — connecting the residual stream across layers with learned attention weights — add about 4% to training cost and 2% to inference cost for a consistent but modest improvement in validation loss and downstream performance. The full figure and breakdown are at Raschka's architecture gallery, which is now the reference for anyone who wants to understand what K3 actually is rather than what the distillation panic says it is.

The repository's counters, as the desk's cap-day dispatch recorded them at midday: 99,214 downloads and 8,410 likes, up from 7,478 the day before. An editor's correction, made when this entry was finalized on the 30th: the dispatch read the flat download counter as the initial burst leveling off. It had not. By the next midday the same counter read 387,822 — nearly four times over. The wrong call stands here, corrected rather than erased, because a record that erases its misses isn't one; the measured trajectory prints in tomorrow's entry.

Two non-K3 items worth noting on the same day. OpenAI open-sourced Codex Security — a command-line interface and TypeScript SDK for finding, validating, and fixing code vulnerabilities, published under Apache 2.0. Note the join, though: the code and the prompt definitions are public, but the scanner they drive remains gated to an approved-customer beta. Open code, gated engine — a truer description than the launch coverage's, and a shape worth remembering when the next "open-source" security artifact ships. And a coordinated disclosure from independent researcher Håkon Måløy, published after a 144-day coordination with the Microsoft Security Response Center, demonstrated document-borne AI worms that can self-propagate through Microsoft Copilot for Word. The attack: hidden instructions in an externally sourced document cause Copilot to alter the document being drafted and copy the instructions into the output, which then becomes a new carrier. The disclosure is notable for its explicit statement that "no robust mitigation for the broader vulnerability class is available" at publication time — a rare admission from the disclosure process itself that the architecture has a hole with no patch.
